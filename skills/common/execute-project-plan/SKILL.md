# 执行项目计划 (Execute Project Plan)

约定 `<skill_dir>` 为本技能所在目录。

## 何时使用

- 已有实施计划文件，需要按步骤分步执行
- 用户要求「执行计划」、「分步推进」或「从第 N 步开始执行」

**前提：** 需要一份已写就的计划文件（通常由 `write-project-plan` 技能产出）。若无计划文件，应先使用 `write-project-plan` 编写计划。

## 核心流程

### 1. 确认与分工

向用户简述计划的目标、关键步骤和验证手段，询问是否同意或有调整建议。**只有用户明确同意后方可执行，严禁在此阶段修改业务代码。**

确认后必须先尝试派生 subagent，避免后续执行时忽略本技能的 subagent 优化要求：

- **派生成功则交给 subagent 执行**：计划步骤边界清晰、验证命令明确、无需频繁交互，或任务跨文件较多但可按步骤独立推进时，主 Agent 不得直接代替执行
- **仅在派生失败或不适合时主 Agent 自行执行**：涉及高风险线上操作、需要用户实时决策、计划本身需要大量修订，或当前环境没有可用 subagent 能力
- **回退需说明原因**：若未使用 subagent，主 Agent 必须在执行记录或最终汇报中简述原因，如「无可用 subagent 能力」或「本步需用户实时决策」
- **分工原则**：主 Agent 负责确认计划、拆分任务、传达边界、审查 subagent 结果和最终汇报；subagent 只负责被分配的单步或一组强相关原子改动

### 2. 执行

严格按照计划分步实施：

- **单步原则**：一次只执行计划中的一个步骤（或一组强相关的原子改动）
- **subagent 任务边界**：每次委派时必须说明计划文件位置、当前步骤编号、允许修改的文件/目录、必须执行的验证、禁止事项和预期回传内容
- **PR 合并限制**：即使计划中包含 PR 流程，Agent 也只能准备、提交、推送或创建/更新 PR；严禁自行合并 PR。必须由用户明确发起合并指令，或交由用户/仓库负责人手动合并
- **状态同步**：
  - **开始任务前**：将任务 `**状态：**` 行从 `未开始` 更新为 `进行中`
  - **每步验证通过后**：将该步骤的 `- [ ]` 更新为 `- [x]`
  - **任务完成标志达成后**：将任务 `**状态：**` 行从 `进行中` 更新为 `已完成`，记录完成日期（如 `**状态：** 已完成 (2026-05-11)`）
- **变更管理**：若发现原计划有误或需调整，必须先更新计划文件并告知用户，获得确认后再继续
- **改动最小化**：每步只做与该步骤相关的改动，避免顺手修改无关代码

#### subagent 委派模板

委派给 subagent 时，按下列信息组织任务，避免丢上下文：

```text
请按计划文件 <plan_path> 执行第 <step_id> 步。
边界：
- 只修改：<allowed_paths>
- 不要修改：<forbidden_paths_or_behaviors>
- 必须遵守：<repo_or_skill_conventions>

验证：
- 运行：<commands>
- 若失败，先在本步骤范围内修复；无法修复时停止并回报错误。

回传：
- 改了哪些文件
- 验证命令和结果
- 计划文件中已更新的状态/验证记录
- 未解决问题或需要主 Agent 决策的点
```

### 3. 验证

每步完成后必须立即验证：

- 按照计划中定义的验证方式执行
- **主 Agent 复核**：subagent 回传后，主 Agent 必须检查 diff、计划文件状态和验证结果；必要时补跑轻量验证，不能只转述 subagent 结论
- **验证失败**：必须在本步内修复，直到验证通过。严禁带病进入下一步
- **记录结果**：在计划文件中该步骤下方追加验证结果行（如 `> 验证通过 (2026-05-11)` 或 `> 验证失败：[具体报错]，已修复 (2026-05-11)`）

### 4. 推进

- 任务完成标志达成后，更新任务状态为 `已完成 (日期)`，向用户汇报进度
- 全部任务完成后，在计划文件头部追加 `**状态：** 已完成 (日期)`

## 核心原则

- **先确认，后执行**：没有用户确认，不动代码
- **严格按计划执行**：不做计划外的改动
- **一步一验证**：每步必验证，验证必通过
- **改动最小化**：每步只做与该步相关的改动
- **主 Agent 对结果负责**：即使由 subagent 执行，也必须由主 Agent 审查变更、同步状态并向用户汇报
- **禁止自行合并 PR**：计划执行到 PR 阶段时，最多推进到可审查/可合并状态；是否合并必须等待用户或仓库负责人确认
